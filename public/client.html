🖥 Kirby Retro Launcher

Le navigateur suffit pour la plupart des consoles — mais la DS, la N64 et la PSX sont bien plus fluides avec un émulateur natif. Ce petit client tout-en-un (rien à installer) reprend la bibliothèque du site et lance chaque jeu dans RetroArch ou un émulateur standalone (melonDS, DuckStation…). Les ROMs absentes se téléchargent automatiquement depuis le site.

Nouveau en 1.8.2 : correctifs Linux — certificats SSL et lancement des jeux via RetroArch Flatpak (Fedora, openSUSE…). Depuis 1.8.1 : versions exécutables autonomes — Windows (.exe) et Linux — Python n'est plus à installer. Et depuis 1.8.0 : sauvegardes détectées automatiquement (RetroArch par core, melonDS, Dolphin…) puis importées au lancement.
(1.7.0 : interface plus sobre. 1.6.0 : bouton SAUVEGARDES.)

🪟 Installation — Windows

  1. Télécharge le launcher (bouton .exe ci-dessus) et pose-le où tu veux (ex. Documents\) — c'est un fichier unique, aucune installation. Au premier lancement, Windows peut afficher un avertissement (fichier non signé) : Informations → Exécuter quand même.
  2. Installe RetroArch — retroarch.com → Download (Windows 64-bit). Lance RetroArch une fois, puis Online Updater → Manage Cores et installe les cores de tes consoles (voir la liste plus bas : melonDS DS pour la DS, Mupen64Plus-Next pour la N64…).
  3. Lance le launcher — double-clic sur kirby-retro-launcher-1.8.2-windows.exe. La fenêtre s'ouvre, la bibliothèque se charge et RetroArch est détecté automatiquement.
  4. (Recommandé) Associe les liens du site — dans le launcher : Paramètres → « Associer les liens kirbyretro:// ». Ensuite, le bouton « Launcher natif » du site ouvre directement le jeu, sans passer par une fenêtre de choix.
  5. Joue — double-clic sur un jeu : la ROM se télécharge dans %USERPROFILE%\KirbyRetroROMs (modifiable dans Paramètres) et l'émulateur se lance.

🐧 Installation — Linux

  1. Télécharge le launcher (bouton binaire ci-dessus), rends-le exécutable et lance-le : 
    chmod +x kirby-retro-launcher-1.8.2-linux
./kirby-retro-launcher-1.8.2-linux
    La bibliothèque se charge ; RetroArch et les cores sont détectés automatiquement : paquet système (dnf/apt/pacman), Flatpak, snap, portable — cores cherchés dans ~/.config/retroarch/cores, /usr/lib*/libretro, le dossier Flatpak, et celui déclaré dans retroarch.cfg.
  2. Installe RetroArch selon ta distribution : 
    # Fedora / Nobara
sudo dnf install retroarch

# Debian / Ubuntu / Mint
sudo apt install retroarch

# Ou en Flatpak (détecté aussi)
flatpak install flathub org.libretro.RetroArch
    Puis, dans RetroArch : Online Updater → Manage Cores (ou installe les paquets libretro-* de ta distribution).
  3. (Recommandé) Associe les liens du site : 
    ./kirby-retro-launcher-1.8.2-linux install-protocol
    Aucun droit root nécessaire. Tu peux aussi le faire via Paramètres → « Associer les liens kirbyretro:// ».
  4. Joue — double-clic sur un jeu : la ROM se télécharge dans ~/KirbyRetroROMs et l'émulateur se lance.

❓ Problèmes fréquents

Sur Windows, la fenêtre run.bat se ferme aussitôt

C'est que Python n'est pas dans le PATH. Réinstalle Python depuis python.org en cochant « Add python.exe to PATH », puis relance run.bat. Le script essaie automatiquement python puis le lanceur py.

« Aucun core RetroArch pour cette console »

Ouvre RetroArch → Online Updater → Manage Cores et installe le core indiqué dans le message (voir le tableau ci-dessus). Relance ensuite Paramètres → Diagnostic pour vérifier.

Le bouton « Launcher natif » du site ne fait rien (ou seulement dans Firefox)

Le navigateur ne sait pas encore quel programme ouvrir pour les liens kirbyretro://. Fais une fois l'étape 5 de l'installation (install-protocol), et c'est réglé.

Firefox : il demande l'autorisation la première fois puis mémorise le choix. Si rien ne s'ouvre : Paramètres → Général → Applications, cherche kirbyretro, choisis « Toujours demander », puis redémarre Firefox (il relit les associations système au démarrage, contrairement à Chrome). En dernier recours : about:config → supprime les clés network.protocol-handler.*.kirbyretro.

Si le launcher ne s'ouvre toujours pas, un bandeau de secours s'affiche en bas de la page avec un bouton « Jouer dans le navigateur » — tu ne restes jamais bloqué.

Sur Linux : « Aucun émulateur configuré » ou « core introuvable »

Mets à jour le launcher en 1.8.2 : il détecte RetroArch installé par dnf, apt, pacman, Flatpak, snap ou en archive, et cherche les cores dans ~/.config/retroarch/cores, /usr/lib*/libretro et le dossier déclaré dans retroarch.cfg.

Vérifie ensuite avec ./run.sh doctor : il affiche les dossiers de cores explorés et les cores trouvés console par console. Il manque un core ? Dans RetroArch : Online Updater → Manage Cores, installe-le, relance le doctor.

Dans le navigateur, la DS affiche un écran noir ou reste bloquée (parfois)

La DS en WASM est exigeante. Essaie, dans l'ordre : mode ⚡ performance (multi-thread), ⚙️ Frame Skip 1–2, désactive les shaders, ou passe en mode compatibilité. Recharge aussi la page (Ctrl+Shift+R) après une mise à jour du site — et vide le cache de l'émulateur si un jeu reste entêté.

Pour la DS, le plus simple reste le launcher natif (RetroArch / melonDS) : c'est beaucoup plus rapide et stable. En cas de doute, le bouton « 🖥 Launcher natif » de la page du jeu fait le nécessaire.

Certains jeux (Saturn, Dreamcast, GameCube…) ne s'ouvrent pas dans le navigateur

Ces consoles n'ont pas d'émulateur navigateur : elles se lancent uniquement via le launcher natif (RetroArch + le core correspondant ; BIOS nécessaire pour la Saturn). Sur la bibliothèque, leurs jeux affichent un badge 🖥 launcher et le clic ouvre directement le launcher. Installe aussi le core dans RetroArch : Online Updater → Manage Cores.

Comment jouer en ligne avec un ami ? (netplay)

Mets à jour le launcher en 1.8.2 chez vous deux, puis :

  1. L'un de vous sélectionne le jeu et clique 🌐 En ligne → Héberger.
  2. Il clique 📋 Copier et envoie l'adresse affichée (Tailscale / réseau local) à l'autre.
  3. L'autre clique 🌐 En ligne → Rejoindre, colle l'adresse et lance la partie.

Astuce : la case relais RetroArch (côté hôte) évite d'ouvrir un port — l'ami rejoint alors via RetroArch → Netplay (actualise et cherche le pseudo de l'hôte, mot de passe optionnel). Idéal sur NES, SNES, Mega Drive, GBA, PSX ; variable sur N64 ; pas disponible pour DS / Wii / PSP. Il faut le même jeu chez les deux — le launcher télécharge les ROMs tout seul.

Où sont mes ROMs et ma configuration ?
  • ROMs : ~/KirbyRetroROMs (dossier par console) — modifiable dans Paramètres ;
  • Config : ~/.config/KirbyRetroLauncher/config.json (%APPDATA%\KirbyRetroLauncher sur Windows) ;
  • Le launcher ne modifie rien chez toi sans action : il télécharge une ROM seulement quand tu cliques sur un jeu.
Je préfère melonDS / DuckStation à RetroArch

Le launcher les détecte automatiquement s'ils sont dans le PATH (et RetroArch reste le repli). Sur Linux, les paquets melonds et duckstation-qt suffisent.

Et macOS ?

Le code est compatible, mais l'association du protocole n'est pas automatisée. Dans le README de l'archive, une section explique la petite manip Automator. Sinon, le mode navigateur reste disponible pour toutes les consoles légères.
